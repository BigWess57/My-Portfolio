Visualiseur : Algorithme LCR

Simulation de l'élection d'un leader par envoi de jetons.

Règles du jeu

Chaque nœud envoie son ID. Quand un nœud reçoit un jeton :

  • Règle 1 (Relais)

    ID Reçu > Son ID : Il est "capturé" (passif) et **retransmet** le jeton.

  • Règle 2 (Absorbé)

    ID Reçu < Son ID : Il "l'absorbe" (détruit) et reste "actif" (candidat).

  • Règle 3 (Élu)

    ID Reçu == Son ID : Il reçoit son propre jeton. Il est **LEADER**.

Journal des Événements

LCR vs Hirschberg–Sinclair

Simplicité : LCR est plus simple. Il n'y a pas de "phases". On envoie juste son ID et on attend.

Nombre de messages : LCR est moins efficace en termes de messages. Dans le pire des cas (si les ID sont triés par ordre croissant sur l'anneau), il peut utiliser $O(N^2)$ messages. Hirschberg–Sinclair est optimisé pour ne jamais dépasser $O(N \log N)$ messages.
